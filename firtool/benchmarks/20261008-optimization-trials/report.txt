Retained implementation

72901c2: Lower firtool shifts and dynamic array reads as whole values.
Recognize the shipped helper bodies, preserve whole-value arithmetic shifts
and variable packed-array reads, and retain ordinary C++ lowering when unsigned
index/offset arithmetic could wrap or helper bodies differ. Existing ROM
preservation remains in place. Linked source nodes fall from 106103 to 64193;
all 5397 state groups remain. Executable text falls from 4888925 to 2586669 bytes.

7dbb0da: Keep native graph chunk-local intermediates in scalar temporaries.
Only values consumed across chunks or by the final state/output phase occupy
shared storage. On the new graph this reduces shared slots from 64193 to 13996
(501.5 KiB to 109.3 KiB), and executable text from 2586669 to 2164749 bytes.
The same graph, chunk size, host models and compiler settings were used in
the paired comparison. Memory-write operand snapshots and simultaneous state
commit semantics are unchanged.

Rejected implementations

3a propagated conservative demand predicates from outputs, register triggers,
memory enables and mux selections. Predicate-producing logic and all its
ancestors were evaluated eagerly before conditionally evaluated data. Distinct
demands merged conservatively to eager computation, avoiding predicate growth.
Per-value conditional expressions were correct but did not improve runtime.

3b regrouped ready DAG nodes sharing the same predicate, preserving dependency
order and the eager control prefix. An entire generated chunk could be skipped
with one guard check. This created 410 chunks (323 conditional calls) versus
110 unguarded chunks, increased shared slots to 18850, and executable text to
2252869 bytes. The measured improvement was only 0.41%. These structural costs
help explain the tradeoff but are not hardware-counter measurements of its
cause. The result rejects these implementations for this workload; it does
not establish that every possible demand-driven scheduler would be ineffective.

Both experiments remain available as guarded-fine.patch and
guarded-regions.patch, each applying independently to 7dbb0da. Neither is active
in the source tree or the default runner.
