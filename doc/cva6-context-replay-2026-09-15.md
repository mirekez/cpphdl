# CVA6 context replay: implemented and checked

## Scope

The register-file replay now preserves the full-model demand classification.
A new bus replay includes the original `axi_xbar_intf`, 2×10 crossbar, both
demuxes, four B/R request trees, downstream muxes and interface packing.
It freshly converts the original SystemVerilog using production elaboration
metadata, then runs cpphdl L1. There are no replacement hardware algorithms
or driver loops manufacturing a chosen number of producer evaluations.

This is a substantially better **bus/RF diagnostic**, not yet a whole-CVA6
performance surrogate. CSR/PMP-to-RVFI observation, issue/scoreboard forwarding
and HPDcache replay-table producers remain outside these cut-outs. Native
whole-design optimization also changes at the cut boundary. Do not infer a
whole-core speedup or regression from the partial/native slowdown ratio.

## Verified behavior

- Capture uses the original native full-CVA6 matmul executable's generated
  hardware and a separate read-only observer executable. Both pass in 46,264
  cycles; an independent audit matches **all 21,285 retirement records** and
  reproduces the exact same bus trace SHA-256:
  `d7851a1529399b30a962702bceb23476990b9096c26194b02aa3eb31e91ba7bc`.
- All **4,052 logical bus output bits**, including idle-cycle values and
  sidebands, match on every one of the 46,264 captured cycles in both replay
  implementations. The one-trace checksum is `0261761b2a1c459e`.
- Bus capture uses synchronized **local reset**, at the settled low-clock
  boundary before each rising edge. Trace parsing and validation are not timed.
- RF replay still matches every captured read pair, with checksum
  `a57c0e15b372e44d`. Its legacy trace uses top-level reset; its three-epoch
  active-count difference from the full-model instrumented decoder is not
  hidden or confused with the bus's local reset trace.

## Measured evaluation counts

Counters run separately from uninstrumented timings. They are placed at the
original generated producer bodies, not helper call sites or guessed loops.
The instrumented bus source bodies match the final fresh regeneration after
removing just the counter hooks.

RF decoder:

| Model | Decoder calls per active epoch |
| --- | ---: |
| Previous isolated L1 replay | 1 |
| New full-context L1 replay | **64** |
| Full CVA6 | **64** |

The new RF checker and one timed trace have 92,508 decoder-active epochs in
total, every one with exactly 64 calls. Calls are generated by the original
2-write-port × 32-register consumer loop. No fixed repetition count is imported.

Bus producer totals, normalized to one 46,264-cycle trace:

| Producer | Full CVA6 calls | Bus replay calls | Difference |
| --- | ---: | ---: | ---: |
| Demux 0 B request tree | 21,455,485 | 22,156,641 | +3.268% |
| Demux 1 B request tree | 21,420,121 | 22,120,856 | +3.271% |
| Demux 0 R request tree | 22,477,149 | 22,541,011 | +0.284% |
| Demux 1 R request tree | 22,061,937 | 22,120,856 | +0.267% |

These are close, **not identical** schedules. Replay trees normally run 478
times per epoch, rising to 563 on some demux-0 epochs. Full-model active counts
are 463–561. Replay reset/observation work also differs; the replay checks all
boundary outputs, whereas full CVA6 has its own conditional consumers. Complete
histograms are retained rather than reducing the evidence to a matching ratio.

## Uninstrumented replay timing

Final fresh-regeneration results, five alternating-order trials on CPU 2,
Clang `-O2` on both sides and production Verilator frontend flags:

| Bus replay | Cycles per timed trial | Median | Min–max |
| --- | ---: | ---: | ---: |
| Verilator | 46,264 | **0.180588 s** | 0.179116–0.182722 s |
| cpphdl L1 + full demand context | 46,264 | **18.461159 s** | 18.369232–18.574331 s |

Every trial first checks the same 46,264-cycle trace outside its timer. All
ten trials report the same cycle count, checked count and checksum. Input
preparation is outside timing; model work, boundary copies and checksum are
inside. These are bus-only times, not full-core times or a claimed 102×
whole-core slowdown. Matching full-design producer counts did **not** preserve
the full native compilation cost at this boundary.

Earlier control runs were approximately 16.7 s / 0.16 s. They are not mixed
into the final medians or presented as an improvement; retained per-trial
records and final build hashes define the result above.

## Profile coverage

Two independent PC-sampling runs pass the same bus checker. They collect
31,242 and 34,021 cpphdl samples; native runs collect 3,461 and 3,420 samples
using twenty trace repetitions. Instrumented durations are not timing results.

| Exclusive PC category | Bus replay run 1 | Run 2 | Prior full-CVA6 profile |
| --- | ---: | ---: | ---: |
| Packed slice writeback | 34.61% | 34.82% | 30.52–30.67% |
| Four B/R request-tree bodies | 18.95% | 19.40% | 9.68–9.93% |
| Packed slice reads | 2.46% | 2.44% | 10.56–10.81% |

The expanded replay exposes the actual expensive request-tree and packed-store
mechanisms rather than only a cheap eager decoder. The reduced slice-read share
also confirms the missing coverage: this bus replay does not include the hot
CSR/RVFI and scoreboard packed-read paths identified in the full-model audit.
These percentages are self-time samples, not module-inclusive timing or proof
that any proposed compiler optimization will transfer to the whole design.

Native replay's first profile is instead dominated by
`ico_sequent__TOP__0` (45.68%) and `nba_sequent__TOP__1` (32.62%). It does not
retain the original full build's two dominant `act_comb` request-copy bodies.
Thus both measured counts and profiles support keeping this as a bus/RF
diagnostic while retaining full CVA6 as the final performance gate.

## Tool changes and conversion bug

`cpphdl --replay-export` exports the original graph's eager/demand classification;
`--replay-context`, `--replay-source` and `--replay-target` import it at a cut
boundary before demand closure. Only additional demand constraints are allowed.
This is not a new production optimizer and does not grant new caching rights.
Without import, default generated full-model C++ remains byte-identical to the
previous validated fixed model. The full export uses its existing serialized
elaboration collections; it is not a fresh full-core SV conversion.

The format rejects malformed/duplicate rows, wrong scheduling mode, module-type
mismatches and completely unmatched paths. It does not fingerprint module
parameters or bodies, so the accompanying source manifests and output/count
checks remain essential. The bus graph has 344 instances, 268 scheduled values,
4,864 dynamic evaluators and 5,739 dynamic states; 8,483 imported nodes match.

Fresh standalone conversion exposed an independent hdlcpp interface bug:
reloading elaboration metadata made synthesized interface-width parameters
look like ordinary declarations, collapsing the master's 5-bit ID width onto
the slave's 4-bit width. The runner failed during binding with an invalid free.
The frontend now retains the configured per-port interface type. It does not
patch generated hardware by hand. Focused independent-width and parent-binding
regressions pass with C++ assertions enabled.

## Controls and limitations

The first native cut-out used default Verilator frontend optimization. I checked
the original full build command and Verilator's local `V3Options::optimize`:
frontend `-O3` enables maximum module inlining. Rebuilding with `-O3`, then with
all relevant original frontend flags (`--unroll-count 256 --vpi --threads-dpi
none --no-timing`), preserves every output but remains about 0.16 s per trace.
**Thus missing frontend flags were not the explanation for the native cost
difference.** The maintained flow nevertheless uses the matching flags.

The full native profile's two large request-copy functions are not reproduced
as the same generated bodies by this cut-out. The boundary therefore remains
inadequate for predicting the full native denominator, even though cpphdl's
request-tree call multiplicities are now close. This limitation is not fixed
by adding synthetic delay or tuning a repetition count.

The previously validated full-model reference remains **32.930 s cpphdl versus
3.474 s native**, 46,264 cycles. This change is replay infrastructure and a
re-conversion correctness fix, **not a measured whole-CVA6 performance fix**.

## Reproduction and tests

Commands and trace layout are in
`hdlcpp/tests/cva6/context_replay/README.md`. The maintained entry points are
`capture_bus.py`, `check_context_replay.py`, and the extended
`check_request_tree.py`. Build inputs, commands and executables are hashed;
timing reuse verifies the recorded files before and after running.

Validation completed:

- 24 optimizer/combs CTest tests; the expanded context test separately checks
  prefix remapping, type mismatch, duplicates, mode mismatch and truncation.
- 19 Python tests, including compiled C++ bus-trace decoder checks.
- Two focused hdlcpp interface-metadata regressions with assertions enabled.
- Full native/capture retirement comparison and all-cycle bus/RF checks.

The Release-built legacy `test_modules` executable also emits
expectation warnings with assertions disabled; it is **not counted as a clean
assertion-enabled full hdlcpp suite pass** here.

Artifacts are under `build/context-replay-20260914/`: full context/export command,
`capture/audit/result.json`, RF/bus `count/run.log`, `count-comparison.json`,
`profiles/report.json`, bus build manifests and timing records. Counter runs
are not speed measurements.
