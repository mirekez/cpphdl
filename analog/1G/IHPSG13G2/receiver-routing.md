# Receiver routing recovery

The 2,400 µm receiver candidate has a saved, legalized post-sizing network.
Its first global-routing attempt completed two 50-iteration overflow-repair
passes, removed a different optional clock-spacing rule after each, and started
a third pass. It did not produce a routed qualification result.

The installed OpenROAD revision `08f67ee5ecd14db5a42be8c610bbfd1ccf079299`
is dated May 12, 2026. It predates the June 30 fix for
[repeated soft-NDR overflow-loop restarts](https://github.com/The-OpenROAD-Project/OpenROAD/pull/10710).
The [upstream investigation](https://github.com/The-OpenROAD-Project/OpenROAD/issues/8466)
identifies the optional CTS double-spacing rules and documents disabling their
generation as a workaround. Ordinary PDK spacing rules still apply.

`physical_module.py --clock-ndr-policy none` enables a receiver-only recovery.
[`receiver_routing.tcl`](receiver_routing.tcl) removes soft rules named
`CTS_NDR_<number>` only from the clock nets found by STA. It rejects custom and
hard-spacing rules before changing any net. A CSV records each removal. Other
module flows retain their existing policy by default.

`--resume-resized-global DIRECTORY` imports the saved receiver database and SDC
into a fresh work directory. It checks the original design/PDK inputs, mapped
netlist and timing contract, records the checkpoint hashes, and verifies the
copied bytes. It then repeats global routing, timing repair, detailed routing,
parasitic extraction, functional replay, electrical/timing acceptance, fill,
DRC and LVS. A saved database carries no previous pass result into this run.

The first recovery was killed by the kernel OOM handler during an unrelated
simulation's waveform export, after about 53 minutes of actual routing. This
was a resource failure, not a routing or timing verdict. A fresh recovery is
queued from the same verified post-sizing checkpoint. The processing-clock
rerun now holds the shared memory slot through export and checking as well as
simulation. Receiver timing, routability and physical qualification remain
open. The maintained physical-flow guards and real OpenDB NDR guard pass
(two CTests, 1.08 seconds). They include changed-checkpoint and changed-timing
rejection, preservation of data-net rules, and atomic rejection of custom or
hard clock rules.

To regenerate from the mapped proof without a saved physical checkpoint, run
from `analog/`:

```sh
pdk/IHPSG13G2/.cpphdl/venv/bin/python 1G/IHPSG13G2/physical_module.py \
  --module PCSReceiver --die-size 2400 --clock-ndr-policy none \
  --mapped-work build/1G/tests/hardware/receiver \
  --work-root build/receiver-physical --workers 1 --route-threads 1
```

The mapped proof must first be regenerated by the receiver hardware flow. For
an interrupted run with a compatible `resized_global.odb` and `.sdc`, add
`--resume-resized-global` with that run's directory. Outputs remain generated
build artifacts; no downloaded tool or checkpoint is required as a committed
source input.
